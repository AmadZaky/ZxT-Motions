# ZxT-Motions — Studio UI refinement / Review 01

Status: proposed design for review. Plugin implementation has not started.
Source: v3.6.0, main commit `53ebc6329e86f32271690610443c30af1cd28bcf`, inspected 4 October 2026 (Asia/Jakarta).

## 1. Goal and boundaries

Select layer → browse/search → select preset → preview/configure in Inspector → Apply → recognize the applied instance → Update in that same Inspector.

Preserve Studio surfaces, dark/light themes, Orange/Lime/Light Blue/Burgundy/White accents, all 134 catalog entries (6 Text Tools FX, 120 Text Animate, 8 SolidGen), YUGraphic credit, current tools, font workflows, Favorites and Recent. Keep Windows / AE 2025 support and existing host guards. No new FX or host-control renaming.

This deliverable is a standalone interaction prototype plus an implementation specification, not a plugin release. No version bump, push, installer modification or website deployment is included. The prototype contains original preset names and core parameter definitions but uses illustrative CSS motion, simulated layers, and simulated operation results. It does not render or edit AE projects.

## 3. Approach decision

Recommended: shared Library + Inspector shell with adapters for core and Text Animate. It gives consistent actions without merging the two animation engines.

Alternatives considered: (a) only re-label the current tabs — low effort, but retains conflicting editor/load paths; (b) rewrite UI and host state from scratch — broad regression risk and unnecessary for this workstream. Use incremental shell migration, with existing regression coverage kept intact.

## 4. Information architecture

| Navigation | Contents |
|---|---|
| **Library** | Text Animate, Text Tools FX and SolidGen collection selector; All / Favorites / Recent; cross-plugin search; preset cards; Inspector. Text Tools FX stays a collapsible highlighted group when viewing text collections. |
| **Motion** | Existing applied-motion entry points; Quick Tools grouped into Anchor & Align, Layers & Rigging, Easing & Curve, Text & Cleanup. Motion Curve retains its full editor here. Applied entries simply select an existing core/IN/OUT record; no stack ordering, blending, chaining or new effect slots. |
| **Create** | Text → Shape → Solid Color. Preserve font preview “M.astra”, host font search/source filtering, separate family/style, size and color. Preserve circle/square/polygon, HEX input and recent/favorite swatches. |
| **Settings** | Header gear; Appearance, control layout, reduce preview animation, connection refresh, diagnostics, author credits and activity history. Restore previous destination on exit. |

Header: brand, search shortcut, theme toggle, gear. Selected-layer bar directly below navigation, 32–36px high: type icon, ellipsized name (full accessible label), lock/mixed status and compact Applied control. Details are optional and height-bounded. No permanent button row for every layer. Search opens/focuses the existing library search, or tool results when outside Library.

Cards: square artwork, two-line maximum name, quiet group label, star. The whole card's select button supports Enter/Space; star is a separate sibling control. Selected outline and small Applied badge distinguish browsing from what is on the target. Hover/focus plays only the active preview; reduced-motion users get a static image plus explicit Replay. YU preview text stays **Motion**; credit remains in collection help and About.

## 5. Responsive contract

| Available panel size | Behavior |
|---|---|
| ≥760px wide | Library + 300px Inspector visible together; library uses remaining width with at least two card columns. Empty Inspector gives guidance until a preset is selected. |
| 300–759px wide | Library OR full-width Inspector detail. Back to Library restores exact collection, search query, Favorites/Recent filter, scroll offset and focus on selected card. |
| <480px high | Compact headers and preview; Inspector body scrolls independently. Primary action row and status remain separate, reachable layout rows. |
| 300×360 minimum test | No horizontal document/panel overflow; controls use full-width or stacked fields; no fixed overlay obscures buttons. If content cannot fit, only content scrolls. |

Breakpoint is based on library width + Inspector width, not user-agent detection. During implementation, use viewport media queries or measured panel width supported by CEP; prototype ResizeObserver is for the review surface. Also test 759/760/761px, 920px, 1200px, 200% UI scaling and long names. Do not claim high-DPI AE validation from Chromium alone.

Use one border system, 6–8px corner radius, 8/12/16px spacing, 12px body and 10–11px secondary labels. Focus rings and selected states follow the accent. Verify text/button contrast in every theme/accent before integration. Avoid per-card descriptive paragraphs and multiple competing Apply buttons.

## 6. Inspector and action state machine

| State | Primary action | Feedback / transition |
|---|---|---|
| No preset | Disabled: Select a preset | Empty Inspector guidance. |
| Valid target, new preset | Apply; SolidGen: Generate Background | Target name/type and concise capability message. No mutations on selection or preview. |
| Matching existing instance, clean | Disabled Update | Applied badge and “Up to date”; load host settings into same Inspector. |
| Matching instance, dirty | Update | “Unsaved changes”; explicit edited fields only. |
| Operation pending | Disabled Working… | Disable all mutations/navigation that could retarget the request. Preserve form values. |
| Success | Update, clean | Reconcile host selection and instance identity, load saved settings without changing tab/scroll; only then show Applied. |
| Partial success | Review targets | Report successes/failures separately; retain failed-target edits. Do not mark all layers clean. |
| Lost reply / uncertain outcome | Check result | Refresh/read host status; never automatically replay a mutation. |
| Invalid values, wrong type, locked, no comp | Disabled relevant action | Persistent actionable inline reason. Browsing remains available. |
| Selection changed with draft | Disabled action | Preserve draft; show old/new target. Explicit Load selected target or return to old layer; never silently transfer the edit. |
| Same target externally changed / Undo | Refresh required | Re-read identity and settings; keep dirty draft pending user resolution. |
| Protected custom animation | Disabled/rejected Update | Explain which control/phase must be edited in AE; retain explicit Remove action with existing confirmation flow. |

Core, YU IN and YU OUT are separate existing records. A compact Applied menu chooses which record to inspect. Picking a different core preset must honor current host preflight; never delete the old instance automatically. For multiple valid text targets: show explicit target count and skips before first Apply; after Apply, show per-target result and require a single target to edit through Inspector. Phase selection must be explicit for YU.

Preserve numeric/text/color drafts per preset and target identity (comp, layer, instance token, phase), not merely preset ID. Current preset-only drafts are not enough for this new flow. Discard restores the loaded baseline without modifying AE. Search, category, collection filter, scroll and focused item are library navigation state, independent of Inspector drafts.

## 7. Post-Apply recognition and safety

For single-target success, resolve the applied instance with existing core `load` or YU `load` phase calls after status. If user selection changed during execution, display success for the original target but block editing until that target is selected again. Do not infer success from a toast or layer name. Background generation resolves the newly created layer/token; repeat action on matching selected background updates it, not another layer.

Unrelated Update must not add keys, override a custom expression or rebuild artwork. Explicit keyframeable control edits retain current v3.6 CTI behavior. Consume edited-field intent after successful Apply as well as Update, so an old color/Progress/Choice edit is not replayed at the next CTI. Mixed partial-success handling needs per-target results before dirty-state reconciliation.

Undo/Redo: no new custom history engine. Use AE's existing undo groups. On focus/status refresh, detect missing/replaced instance token or changed saved state and reconcile Inspector. Native values changed independently of metadata require a read-only settings refresh; do not assume unchanged metadata means unchanged native controls. Read-only inspection must never create undo entries. Never introduce auto-Apply on sliders.

## 8. Suggested UI boundaries (not implemented)

- Workspace shell: Library/Motion/Create routing, responsive detail/split presentation, preferences.
- Library state: query, collection, category, scroll, focus; reuse collections store.
- Inspector state: preset adapter, phase, exact target identity, loaded baseline, draft, dirty fields, pending request, result.
- Core/YU adapters: existing validation and request shapes, common display states. Keep host engines isolated.
- Selection context: existing bounded status payload, stale-target check, Applied selector.
- Feedback: brief success in reserved footer; persistent inline errors/partial outcomes with recovery. No overlapping toasts.

Do not reformat or rewrite host engines merely to relocate UI. Implement navigation and presentation first, then the post-Apply reconciliation contract with tests.

## 10. Sequencing and review decision

1. **This review:** approve navigation grouping, compact header, card selection, responsive Inspector, and single primary action states.
2. **Studio implementation:** preserve controllers/engines and migrate UI incrementally; add navigation/state regression tests; verify native AE gate before claiming full reliability.
3. **Smart Workflow:** contextual target handling and fewer manual load steps after the shared UI is stable; explicit batch-result resolution.
4. **Post-Apply controls:** deliberate timing, phase, loop and keyframe workflows through the same Inspector, with protected-animation feedback.
5. **Copy/Paste Motion:** define copied scope, target compatibility, time mapping and overwrite policy before building.
6. **Motion Stack:** deferred. No stack UI or blending semantics in this workstream.

Prototype review steps: choose a width → search “Counter” or choose an animation → select card → edit and Apply → edit and Update → Back to Library → change simulated selection → inspect stale-target handling. Try star/Recent, light mode, accents, and simulated Undo/Redo. Motion/Create show navigation placement only; their existing AE functions are not ported into the mockup.
